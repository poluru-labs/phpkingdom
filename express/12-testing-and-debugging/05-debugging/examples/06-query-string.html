Study the Express route/middleware pattern and adapt it to your API.

Express

// Express Debugging — Example 06
// Focus: query string | Scenario: ecommerce API

// DEBUG=express:* node server.js
// Or: node --inspect server.js → Chrome chrome://inspect

app.use((req, res, next) => {
  console.log(JSON.stringify({
    method: req.method,
    url: req.url,
    requestId: req.requestId,
  }));
  next();
});

app.use((err, req, res, next) => {
  console.error("ERR", err.message, err.stack);
  next(err);
});
// Log request ids; avoid logging secrets or full bodies in production

Practice Notes

Checklist for Express Debugging
- Practice: query string
- Scenario: ecommerce API
- Keep route handlers thin; push logic into controllers/services
- Always attach final 4-arg error middleware
- Validate input; load secrets from environment variables
- Export app separately from listen() for easier testing
