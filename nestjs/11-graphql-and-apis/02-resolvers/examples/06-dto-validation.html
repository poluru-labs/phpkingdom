Example 06

GraphQL Resolvers

Section: GraphQL and APIs

Focus: Dto Validation

Scenario: billing microservice

Study the NestJS module/controller/service pattern and adapt it to your API.

NestJS

// GraphQL Resolvers — Example 06
// Focus: dto validation | Scenario: billing microservice

import { Resolver, Query, Mutation, Args, Int } from "@nestjs/graphql";
import { UsersService } from "./users.service";
import { User } from "./user.model";
import { CreateUserInput } from "./create-user.input";

@Resolver(() => User)
export class UsersResolver {
  constructor(private users: UsersService) {}

  @Query(() => User, { name: "user" })
  findOne(@Args("id", { type: () => Int }) id: number) {
    return this.users.findOne(id);
  }

  @Mutation(() => User)
  createUser(@Args("input") input: CreateUserInput) {
    return this.users.create(input);
  }
}

Practice Notes

Checklist for GraphQL Resolvers
- Practice: dto validation
- Scenario: billing microservice
- Structure by feature modules: module + controller + service + DTOs
- Prefer constructor injection; keep providers @Injectable()
- Validate input with class-validator + ValidationPipe (whitelist)
- Use guards for auth/roles, pipes for transform/validate, filters for errors
- Test with TestingModule; e2e with supertest against NestFactory

Useful commands:
  npm i -g @nestjs/cli
  nest new my-api
  nest g resource users
  nest start --watch
  npm run test
  npm run test:e2e
