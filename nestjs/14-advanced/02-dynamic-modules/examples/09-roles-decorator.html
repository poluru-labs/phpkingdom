Dynamic Modules

Study the NestJS module/controller/service pattern and adapt it to your API.

NestJS

// Dynamic Modules — Example 09
// Focus: roles decorator | Scenario: IoT gateway

import { DynamicModule, Module, Global } from "@nestjs/common";

export interface CacheOptions {
  ttl: number;
  prefix?: string;
}

@Global()
@Module({})
export class CacheModule {
  static forRoot(options: CacheOptions): DynamicModule {
    return {
      module: CacheModule,
      providers: [
        { provide: "CACHE_OPTIONS", useValue: options },
        {
          provide: "CACHE",
          useFactory: (opts: CacheOptions) => ({
            get: (k: string) => null,
            set: (k: string, v: unknown) => undefined,
            ttl: opts.ttl,
          }),
          inject: ["CACHE_OPTIONS"],
        },
      ],
      exports: ["CACHE"],
    };
  }
}
// CacheModule.forRoot({ ttl: 60, prefix: "app:" })

Practice Notes

Checklist for Dynamic Modules
- Practice: roles decorator
- Scenario: IoT gateway
- Structure by feature modules: module + controller + service + DTOs
- Prefer constructor injection; keep providers @Injectable()
- Validate input with class-validator + ValidationPipe (whitelist)
- Use guards for auth/roles, pipes for transform/validate, filters for errors
- Test with TestingModule; e2e with supertest against NestFactory

Useful commands:
  npm i -g @nestjs/cli
  nest new my-api
  nest g resource users
  nest start --watch
  npm run test
  npm run test:e2e
