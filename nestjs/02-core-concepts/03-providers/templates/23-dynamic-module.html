NestJS

// NestJS Providers — Template 23
// Focus: dynamic module | Scenario: e-commerce API

import { Injectable, Module } from "@nestjs/common";

@Injectable()
export class MailerService {
  send(to: string, subject: string) {
    return { to, subject, queued: true };
  }
}

// Custom provider token
export const SMTP_URL = "SMTP_URL";

@Module({
  providers: [
    MailerService,
    { provide: SMTP_URL, useValue: "smtp://localhost:1025" },
  ],
  exports: [MailerService],
})
export class MailModule {}
// Providers are injectable classes, values, factories, or existing aliases

Practice Notes

Checklist for NestJS Providers
- Practice: dynamic module
- Scenario: e-commerce API
- Structure by feature modules: module + controller + service + DTOs
- Prefer constructor injection; keep providers @Injectable()
- Validate input with class-validator + ValidationPipe (whitelist)
- Use guards for auth/roles, pipes for transform/validate, filters for errors
- Test with TestingModule; e2e with supertest against NestFactory

Useful commands:
  npm i -g @nestjs/cli
  nest new my-api
  nest g resource users
  nest start --watch
  npm run test
  npm run test:e2e
