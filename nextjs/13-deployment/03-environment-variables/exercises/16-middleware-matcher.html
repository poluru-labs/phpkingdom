Environment Variables

Section: Deployment

Focus: Middleware Matcher

Scenario: admin console

Implement the focus in a local create-next-app project and verify in the browser.

Next.js

// Environment Variables — Exercise 16
// Focus: middleware matcher | Scenario: admin console

// .env.local
// NEXT_PUBLIC_API_BASE=https://api.example.com
// DATABASE_URL=postgres://...   # server-only

export default async function Page() {
  const publicBase = process.env.NEXT_PUBLIC_API_BASE;
  const dbUrl = process.env.DATABASE_URL; // never expose to Client Components
  return (
    <p>
      Public API: {publicBase}
      {/* dbUrl stays on the server */}
    </p>
  );
}

Practice Notes

Checklist for Environment Variables
- Practice: middleware matcher
- Scenario: admin console
- Prefer App Router: app/, layout.tsx, page.tsx, loading.tsx, error.tsx
- Default to Server Components; add "use client" only when needed
- Cache intentionally: fetch options, revalidate, tags, no-store
- Use Route Handlers / Server Actions for backend work in the same app
- Optimize with next/image, next/font, and Metadata API

Useful commands:
  npx create-next-app@latest
  npm run dev
  npm run build && npm start
