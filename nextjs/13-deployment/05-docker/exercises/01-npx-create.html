// Docker with Next.js — Exercise 01
// Focus: npx create | Scenario: marketing site

# Dockerfile (standalone)
# FROM node:20-alpine AS deps
# WORKDIR /app && COPY package*.json ./ && npm ci
# FROM node:20-alpine AS builder
# ... npm run build
# FROM node:20-alpine AS runner
# COPY --from=builder /app/.next/standalone ./
# COPY --from=builder /app/.next/static ./.next/static
# COPY --from=builder /app/public ./public
# EXPOSE 3000
# CMD ["node", "server.js"]

# next.config: output: "standalone"

Practice Notes

Checklist for Docker with Next.js
- Practice: npx create
- Scenario: marketing site
- Prefer App Router: app/, layout.tsx, page.tsx, loading.tsx, error.tsx
- Default to Server Components; add "use client" only when needed
- Cache intentionally: fetch options, revalidate, tags, no-store
- Use Route Handlers / Server Actions for backend work in the same app
- Optimize with next/image, next/font, and Metadata API

Useful commands:
  npx create-next-app@latest
  npm run dev
  npm run build && npm start
  npx next lint
  ANALYZE=true npm run build  # with @next/bundle-analyzer

Notes

This exercise shows one way to apply Docker with Next.js in a marketing site context.

Keep Server Components as the default, cache deliberately, and ship with Metadata + image/font optimization.
