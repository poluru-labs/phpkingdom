// DOM Assertions — Example 05
// Focus: data attribute selectors | Scenario: auth portal

describe("DOM assertions", () => {
  it("checks visibility, attributes, and presence", () => {
    cy.visit("/modal-demo");
    cy.get("[data-cy=open-modal]").click();
    cy.get("[data-cy=modal]")
      .should("be.visible")
      .and("have.attr", "role", "dialog");
    cy.get("[data-cy=modal-close]").click();
    cy.get("[data-cy=modal]").should("not.exist");
  });
});

Practice Notes

Checklist for DOM Assertions
- Practice: data attribute selectors
- Scenario: auth portal
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
