// Form Assertions — Example 21
// Focus: a11y check | Scenario: SaaS dashboard

describe("form assertions", () => {
  it("validates values, enabled state, and errors", () => {
    cy.visit("/register");
    cy.get("[data-cy=email]").type("not-an-email");
    cy.get("[data-cy=submit]").click();
    cy.get("[data-cy=email-error]").should("contain", "valid email");
    cy.get("[data-cy=email]")
      .clear()
      .type("ada@phpkingdom.com")
      .should("have.value", "ada@phpkingdom.com")
      .and("be.enabled");
  });
});

Practice Notes

Checklist for Form Assertions
- Practice: a11y check
- Scenario: SaaS dashboard
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
