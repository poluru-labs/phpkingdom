// Cypress Assertions — Exercise 09
// Focus: config tweak | Scenario: docs site

describe("assertions overview", () => {
  it("mixes implicit should and explicit expect", () => {
    cy.visit("/status");
    cy.get("[data-cy=status]")
      .should("have.class", "ok")
      .and("contain", "Healthy");
    cy.get("[data-cy=latency]").invoke("text").then((t) => {
      expect(Number(t)).to.be.lessThan(200);
    });
  });
});

Practice Notes

Checklist for Cypress Assertions
- Practice: config tweak
- Scenario: docs site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
