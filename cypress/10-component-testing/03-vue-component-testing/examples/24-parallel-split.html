// Vue Component Testing — Example 24
// Focus: parallel split | Scenario: admin panel

import Toggle from "./Toggle.vue";

describe("Toggle.vue", () => {
  it("toggles aria-pressed", () => {
    cy.mount(Toggle, { props: { label: "Dark mode" } });
    cy.get("[data-cy=toggle]")
      .should("have.attr", "aria-pressed", "false")
      .click()
      .should("have.attr", "aria-pressed", "true");
  });
});
// cypress.config → component.devServer.framework: "vue"

Practice Notes

Checklist for Vue Component Testing
- Practice: parallel split
- Scenario: admin panel
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
