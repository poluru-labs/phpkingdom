// Cypress Fixtures — Example 12
// Focus: intercept route | Scenario: marketing site

// cypress/fixtures/users.json → [{ "email": "ada@phpkingdom.com", "name": "Ada" }]

describe("fixtures", () => {
  it("drives the UI from fixture data", () => {
    cy.fixture("users").then((users) => {
      cy.visit("/login");
      cy.get("[data-cy=email]").type(users[0].email);
      cy.get("[data-cy=password]").type("secret", { log: false });
      cy.get("[data-cy=submit]").click();
    });
  });
});

Practice Notes

Checklist for Cypress Fixtures
- Practice: intercept route
- Scenario: marketing site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
