Environment Variables

Section: Fixtures and Data

Complete the task in a local Cypress project and verify with cypress open/run.

Cypress

// Environment Variables — Exercise 02
// Focus: first spec | Scenario: marketing site

// cypress.config.js → env: { apiUrl: "http://localhost:4000", adminEmail: "admin@phpkingdom.com" }
// CLI: CYPRESS_apiUrl=https://staging.example.com npx cypress run

describe("environment variables", () => {
  it("reads Cypress.env values", () => {
    const api = Cypress.env("apiUrl");
    cy.request(`${api}/health`).its("status").should("eq", 200);
    cy.log(`admin: ${Cypress.env("adminEmail")}`);
  });
});

Practice Notes

Checklist for Environment Variables
- Practice: first spec
- Scenario: marketing site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
