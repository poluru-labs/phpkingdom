// Cypress Do's and Don'ts — Template 05
// Focus: api kit | Scenario: auth portal

describe("dos and donts", () => {
  it("DO assert UI readiness; DON'T sleep", () => {
    cy.visit("/feed");
    // DO:
    cy.get("[data-cy=feed-item]").should("have.length.greaterThan", 0);
    // DON'T: cy.wait(5000);
  });

  it("DO use data-cy; DON'T chain off CSS animations casually", () => {
    cy.get("[data-cy=menu]").click();
    cy.get("[data-cy=menu-panel]").should("be.visible");
  });
});

Practice Notes

Checklist for Cypress Do's and Don'ts
- Practice: api kit
- Scenario: auth portal
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
