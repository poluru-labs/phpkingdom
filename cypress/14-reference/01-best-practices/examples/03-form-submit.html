// Cypress Best Practices — Example 03
// Focus: form submit | Scenario: checkout flow

describe("best practices checklist", () => {
  it("keeps tests independent and selector-stable", () => {
    cy.session("bp-user", () => {
      cy.visit("/login");
      cy.get("[data-cy=email]").type("ada@phpkingdom.com");
      cy.get("[data-cy=password]").type("secret", { log: false });
      cy.get("[data-cy=submit]").click();
    });
    cy.visit("/app");
    cy.get("[data-cy=home]").should("be.visible");
  });
});
// 1) data-cy  2) retry-ability  3) isolation + cy.session  4) intercept flaky APIs

Practice Notes

Checklist for Cypress Best Practices
- Practice: form submit
- Scenario: checkout flow
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
