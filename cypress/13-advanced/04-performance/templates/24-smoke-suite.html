// Cypress Performance — Template 24
// Focus: smoke suite | Scenario: admin panel

describe("performance checks", () => {
  it("loads the dashboard under a soft budget", () => {
    cy.visit("/dashboard", {
      onBeforeLoad(win) {
        win.performance.mark("start");
      },
    });
    cy.get("[data-cy=dashboard]").should("be.visible").then(() => {
      cy.window().then((win) => {
        win.performance.mark("ready");
        win.performance.measure("ready", "start", "ready");
        const entry = win.performance.getEntriesByName("ready")[0];
        expect(entry.duration).to.be.lessThan(5000);
      });
    });
  });
});

Practice Notes

Checklist for Cypress Performance
- Practice: smoke suite
- Scenario: admin panel
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
