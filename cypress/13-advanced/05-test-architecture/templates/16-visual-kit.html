describe("architecture — feature folder", () => {
  beforeEach(() => {
    cy.intercept("GET", "/api/projects", { fixture: "projects.json" }).as("projects");
    cy.login("ada@phpkingdom.com", "secret");
    cy.visit("/projects");
    cy.wait("@projects");
  });

  it("lists projects for the session user", () => {
    cy.get("[data-cy=project-card]").should("have.length.greaterThan", 0);
  });
});

Practice Notes

Checklist for Test Architecture
- Practice: visual kit
- Scenario: component library
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
