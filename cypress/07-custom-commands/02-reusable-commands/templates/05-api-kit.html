// Reusable Commands — Template 05
// Focus: api kit | Scenario: auth portal

Cypress.Commands.add("getByCy", (id) => cy.get(`[data-cy=${id}]`));
Cypress.Commands.add("seedDb", (fixture) => {
  cy.task("db:seed", fixture);
});

describe("reusable helpers", () => {
  beforeEach(() => {
    cy.seedDb("demo");
    cy.visit("/");
  });

  it("uses getByCy everywhere", () => {
    cy.getByCy("hero").should("be.visible");
    cy.getByCy("cta").click();
  });
});

Practice Notes

Checklist for Reusable Commands
- Practice: api kit
- Scenario: auth portal
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
