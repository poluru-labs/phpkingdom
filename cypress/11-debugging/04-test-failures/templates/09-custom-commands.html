// Debug Test Failures — Template 09
// Focus: custom commands | Scenario: docs site

describe("debug test failures", () => {
  it("prints response bodies on API failure", () => {
    cy.request({ url: "/api/missing", failOnStatusCode: false }).then((res) => {
      cy.log(JSON.stringify(res.body));
      expect(res.status).to.eq(404);
    });
  });

  afterEach(function () {
    if (this.currentTest.state === "failed") {
      cy.screenshot(`failed-${this.currentTest.title}`);
    }
  });
});

Practice Notes

Checklist for Debug Test Failures
- Practice: custom commands
- Scenario: docs site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
