// Cypress vs Selenium (mental model)
// Cypress: runs in the browser, automatic waiting, network stubbing built-in
// Selenium: WebDriver protocol, multi-language, true multi-tab drivers

// Cypress sketch (same-origin SPA):
cy.visit("/dashboard");
cy.get("[data-cy=nav-settings]").click();
cy.contains("Settings").should("be.visible");

// Selenium-style waits are rarely needed — prefer should() retries
// cy.wait(5000); // avoid — Cypress is not Selenium

Practice Notes

Checklist for Cypress vs Selenium
- Practice: url check
- Scenario: mobile web app
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome

Notes

This example shows one way to apply Cypress vs Selenium in a mobile web app context.

Prefer data-cy selectors, avoid arbitrary waits, and lean on Cypress retries.
