// Cypress Commands — Example 18
// Focus: video record | Scenario: mobile web app

// Built-in commands queue asynchronously but read synchronously in specs

describe("cypress commands", () => {
  it("chains visit → get → type → click", () => {
    cy.visit("/contact");
    cy.get("[data-cy=name]").clear().type("Ada Lovelace");
    cy.get("[data-cy=message]").type("Hello from Cypress");
    cy.get("[data-cy=send]").click();
    cy.contains("[data-cy=toast]", "Sent").should("be.visible");
  });
});
// Each command yields a subject for the next link in the chain

Practice Notes

Checklist for Cypress Commands
- Practice: video record
- Scenario: mobile web app
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
