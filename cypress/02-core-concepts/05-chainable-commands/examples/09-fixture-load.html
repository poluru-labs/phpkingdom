// Chainable Commands — Example 09
// Focus: fixture load | Scenario: docs site

describe("chainable API", () => {
  it("filters and asserts on yielded subjects", () => {
    cy.visit("/docs");
    cy.get("[data-cy=toc] li")
      .should("have.length.at.least", 3)
      .eq(1)
      .find("a")
      .click();
    cy.hash().should("match", /^#/);
  });

  it("uses .then for imperative branching", () => {
    cy.get("[data-cy=price]").invoke("text").then((text) => {
      const dollars = Number(text.replace(/[^0-9.]/g, ""));
      expect(dollars).to.be.greaterThan(0);
    });
  });
});

Practice Notes

Checklist for Chainable Commands
- Practice: fixture load
- Scenario: docs site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
