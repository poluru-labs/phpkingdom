// Cypress Waiting — Example 11
// Focus: custom command | Scenario: SaaS dashboard

describe("waiting strategy", () => {
  it("waits on UI state, not arbitrary ms", () => {
    cy.visit("/reports");
    cy.get("[data-cy=spinner]").should("not.exist");
    cy.get("[data-cy=report-table]", { timeout: 15000 }).should("be.visible");
  });
});
// Default commands already wait/retry — lean on assertions

Practice Notes

Checklist for Cypress Waiting
- Practice: custom command
- Scenario: SaaS dashboard
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
