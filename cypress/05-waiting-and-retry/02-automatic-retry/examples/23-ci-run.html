// Automatic Retry — Example 23
// Focus: ci run | Scenario: checkout flow

describe("automatic retry", () => {
  it("retries get + should until timeout", () => {
    cy.visit("/notifications");
    // App eventually injects the toast — Cypress keeps querying
    cy.get("[data-cy=toast]", { timeout: 10000 })
      .should("be.visible")
      .and("contain", "Synced");
  });
});
// Actionability checks (visibility, not covered) also retry

Practice Notes

Checklist for Automatic Retry
- Practice: ci run
- Scenario: checkout flow
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
