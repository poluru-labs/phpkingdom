// Protected Routes Testing — Example 12
// Focus: intercept route | Scenario: marketing site

describe("protected routes", () => {
  it("redirects anonymous users to login", () => {
    cy.clearCookies();
    cy.visit("/settings");
    cy.location("pathname").should("eq", "/login");
    cy.location("search").should("include", "next=%2Fsettings");
  });

  it("allows authenticated access", () => {
    cy.login("ada@phpkingdom.com", "secret");
    cy.visit("/settings");
    cy.location("pathname").should("eq", "/settings");
  });
});

Practice Notes

Checklist for Protected Routes Testing
- Practice: intercept route
- Scenario: marketing site
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units
