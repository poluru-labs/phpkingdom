Cypress

// Login Testing — Exercise 07
// Focus: fixture usage | Scenario: API-backed SPA

describe("login testing", () => {
  it("shows an error for bad credentials", () => {
    cy.visit("/login");
    cy.get("[data-cy=email]").type("ada@phpkingdom.com");
    cy.get("[data-cy=password]").type("wrong", { log: false });
    cy.get("[data-cy=submit]").click();
    cy.get("[data-cy=login-error]").should("contain", "Invalid");
    cy.location("pathname").should("eq", "/login");
  });

  it("lands on /app after success", () => {
    cy.visit("/login");
    cy.get("[data-cy=email]").type(Cypress.env("userEmail"));
    cy.get("[data-cy=password]").type(Cypress.env("userPassword"), { log: false });
    cy.get("[data-cy=submit]").click();
    cy.location("pathname").should("eq", "/app");
  });
});

Practice Notes

Checklist for Login Testing
- Practice: fixture usage
- Scenario: API-backed SPA
- Prefer data-cy / role-based selectors over brittle CSS
- Lean on Cypress retry-ability; avoid cy.wait(ms)
- Isolate tests; use cy.session for auth speed
- Stub flaky network with cy.intercept; assert with cy.wait('@alias')
- Keep e2e for journeys; use component testing for UI units

Useful commands:
  npm install --save-dev cypress
  npx cypress open
  npx cypress run
  npx cypress run --record --parallel
  npx cypress run --browser chrome
