Module Federation

// Micro Frontend Architecture — Exercise 22
// Focus: debug share | Scenario: admin portal

// Domain-aligned remotes + thin shell (composition root)

// domains/
//   catalog/   → remote "catalog"  exposes ./CatalogApp
//   checkout/  → remote "checkout" exposes ./CheckoutApp
//   shell/     → host "shell"      remotes + layout + auth

const { ModuleFederationPlugin } = require("webpack").container;

// shell/webpack.config.js
new ModuleFederationPlugin({
  name: "shell",
  remotes: {
    catalog: "catalog@http://localhost:3001/remoteEntry.js",
    checkout: "checkout@http://localhost:3002/remoteEntry.js",
  },
  shared: {
    react: { singleton: true, requiredVersion: "^18.0.0" },
    "react-dom": { singleton: true, requiredVersion: "^18.0.0" },
  },
});
// Each domain owns deploy cadence; shell owns navigation + cross-cutting concerns

Practice Notes

Checklist for Micro Frontend Architecture
- Practice: debug share
- Scenario: admin portal
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This exercise shows one way to apply Micro Frontend Architecture in a admin portal context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
