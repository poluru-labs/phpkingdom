Module Federation

// First Federated Application — Template 11
// Focus: event bus kit | Scenario: e-commerce shell

// First federated app — host shell + products remote

// Terminal A — remote
// npx webpack serve --config webpack.remote.js --port 3002

// Terminal B — host
// npx webpack serve --config webpack.host.js --port 3000

// webpack.remote.js
new ModuleFederationPlugin({
  name: "products",
  filename: "remoteEntry.js",
  exposes: { "./ProductList": "./src/ProductList" },
  shared: { react: { singleton: true }, "react-dom": { singleton: true } },
});

// Host App: const ProductList = lazy(() => import("products/ProductList"));
// Verify Network tab shows remoteEntry.js from :3002

Practice Notes

Checklist for First Federated Application
- Practice: event bus kit
- Scenario: e-commerce shell
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This template shows one way to apply First Federated Application in a e-commerce shell context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
