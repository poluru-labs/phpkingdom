shared: {
  vue: { singleton: true, requiredVersion: "^3.3.0" },
}

// Host
import { defineAsyncComponent } from "vue";
const Remote = defineAsyncComponent(() => import("products/ProductList"));

// Remote exposes .vue SFCs or mount() helpers
// Share vue-router / pinia as singletons when used across boundaries

Practice Notes

Checklist for Module Federation with Vue
- Practice: e2e shell
- Scenario: B2B portal
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This template shows one way to apply Module Federation with Vue in a b2b portal context.
