Vue Host Application

Section: Vue Integration

Focus: Lazy Route

Scenario: mobile web shell

Study the host/remote federation pattern and adapt it to your micro-frontend setup.

Module Federation

// Vue Host Application — Example 09
// Focus: lazy route | Scenario: mobile web shell

// Vue 3 host with Module Federation

const { ModuleFederationPlugin } = require("webpack").container;

new ModuleFederationPlugin({
  name: "shell",
  remotes: {
    products: "products@http://localhost:3002/remoteEntry.js",
  },
  shared: {
    vue: { singleton: true, requiredVersion: "^3.3.0" },
  },
});

// App.vue
<script setup>
import { defineAsyncComponent } from "vue";
const ProductList = defineAsyncComponent(() => import("products/ProductList"));
</script>

<template>
  <Suspense>
    <ProductList />
    <template #fallback>Loading…</template>
  </Suspense>
</template>

Practice Notes

Checklist for Vue Host Application
- Practice: lazy route
- Scenario: mobile web shell
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This example shows one way to apply Vue Host Application in a mobile web shell context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
