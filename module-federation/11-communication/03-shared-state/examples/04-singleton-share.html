// Shared state options for MF

// A) Host owns state, passes props / callbacks into remotes
// B) Shared library (zustand/redux) listed in shared: { singleton: true }
// C) Event bus / CustomEvent for loose coupling
// D) URL query as source of truth

// shared zustand store package @acme/session
import { create } from "zustand";
export const useSession = create((set) => ({
  user: null,
  setUser: (user) => set({ user }),
}));

// webpack shared: { "@acme/session": { singleton: true } }
// Both host and remotes import from the same singleton module instance

Practice Notes

Checklist for Shared State
- Practice: singleton share
- Scenario: checkout remote
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This example shows one way to apply Shared State in a checkout remote context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
