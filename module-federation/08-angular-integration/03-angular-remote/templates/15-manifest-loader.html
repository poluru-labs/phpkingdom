Module Federation

// Angular Remote Application — Template 15
// Focus: manifest loader | Scenario: profile remote

// Angular remote exposes a component or routes

new ModuleFederationPlugin({
  name: "products",
  filename: "remoteEntry.js",
  exposes: {
    "./Module": "./src/app/products/products.module.ts",
    "./Routes": "./src/app/products/products.routes.ts",
  },
  shared: {
    "@angular/core": { singleton: true, strictVersion: true, requiredVersion: "auto" },
    "@angular/common": { singleton: true, strictVersion: true, requiredVersion: "auto" },
  },
});

// Prefer standalone components + route arrays for modern Angular
// Keep zone.js strategy consistent with the host

Practice Notes

Checklist for Angular Remote Application
- Practice: manifest loader
- Scenario: profile remote
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002
