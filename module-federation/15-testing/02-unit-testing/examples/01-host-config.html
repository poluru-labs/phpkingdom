// Unit-test remote components in isolation (Jest/Vitest)

// ProductList.test.jsx
import { render, screen } from "@testing-library/react";
import ProductList from "./ProductList";

test("renders items", () => {
  render(<ProductList items={[{ id: "1", name: "Mug" }]} />);
  expect(screen.getByText("Mug")).toBeInTheDocument();
});

// Mock federated imports when testing the host:
jest.mock("products/ProductList", () => ({
  __esModule: true,
  default: () => <div>Mock Products</div>,
}));

// Keep business logic in plain modules for easy tests

Practice Notes

Checklist for Unit Testing
- Practice: host config
- Scenario: e-commerce shell
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This example shows one way to apply Unit Testing in a e-commerce shell context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
