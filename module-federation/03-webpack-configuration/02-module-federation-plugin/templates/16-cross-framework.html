Module Federation

// ModuleFederationPlugin — Template 16
// Focus: cross framework | Scenario: design system CDN

const { ModuleFederationPlugin } = require("webpack").container;

// Core options:
// name, filename, exposes, remotes, shared, library, shareScope

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: "products",
      filename: "remoteEntry.js",
      library: { type: "var", name: "products" },
      exposes: { "./Widget": "./src/Widget" },
      remotes: {},
      shared: {
        react: { singleton: true, requiredVersion: "^18.0.0" },
      },
    }),
  ],
};
// Host uses remotes; remote uses exposes; either may use both (bi-di)

Practice Notes

Checklist for ModuleFederationPlugin
- Practice: cross framework
- Scenario: design system CDN
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002
