// products/src/App.jsx
import { Routes, Route } from "react-router-dom";
export default function ProductsApp() {
  return (
    <Routes>
      <Route index element={<List />} />
      <Route path=":id" element={<Detail />} />
      <Route path=":id/reviews" element={<Reviews />} />
    </Routes>
  );
}

// Host: <Route path="/products/*" element={<ProductsApp />} />
// Remote must NOT wrap with BrowserRouter when embedded
// Standalone bootstrap may add MemoryRouter/BrowserRouter for local demos

Practice Notes

Checklist for Remote Routing
- Practice: retry load
- Scenario: legacy migration
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This example shows one way to apply Remote Routing in a legacy migration context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
