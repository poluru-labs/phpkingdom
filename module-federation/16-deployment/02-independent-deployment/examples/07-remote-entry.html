// Independent Deployment — Example 07
// Focus: remote entry | Scenario: multi-team platform

// Remotes deploy without rebuilding the host when contract + URL stay compatible

// CI for products remote:
// 1. npm run build
// 2. upload dist/ to s3://cdn/products/${VERSION}/
// 3. update manifest: products.url = https://cdn/.../products/${VERSION}/remoteEntry.js

// Host reads manifest at runtime (or build-time env):
async function productsUrl() {
  const m = await fetch("/remotes.manifest.json").then((r) => r.json());
  return m.products.url;
}

// Host rebuild only when:
// - shared contract (exposes / props) breaks
// - shared dependency major bumps require host update

Practice Notes

Checklist for Independent Deployment
- Practice: remote entry
- Scenario: multi-team platform
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002

Notes

This example shows one way to apply Independent Deployment in a multi-team platform context.

Keep remotes independently deployable, share carefully, and always plan for remote downtime.
