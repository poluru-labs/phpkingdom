Module Federation

// Runtime Remotes — Example 24
// Focus: native federation | Scenario: checkout remote

// Resolve remotes entirely at runtime (no static remotes map)

import { registerRemotes, loadRemote } from "@module-federation/enhanced/runtime";

registerRemotes([
  {
    name: "marketing",
    entry: "https://cdn.example.com/marketing/mf-manifest.json",
  },
]);

const Hero = React.lazy(() =>
  loadRemote("marketing/Hero").then((m) => ({ default: m.default || m }))
);

export function CampaignSlot() {
  return (
    <React.Suspense fallback={<div>Loading campaign…</div>}>
      <Hero />
    </React.Suspense>
  );
}
// Toggle remotes via config service without rebuilding the shell

Practice Notes

Checklist for Runtime Remotes
- Practice: native federation
- Scenario: checkout remote
- Share framework runtimes as singletons with requiredVersion
- Load remotes lazily; wrap with error boundaries / fallbacks
- Deploy remotes independently; version remoteEntry URLs carefully
- Align CORS and CSP for cross-origin remoteEntry.js

Useful commands:
  npm install -D webpack webpack-cli webpack-dev-server
  # run host + remote on different ports
  npx webpack serve --config webpack.host.js --port 3000
  npx webpack serve --config webpack.remote.js --port 3002
