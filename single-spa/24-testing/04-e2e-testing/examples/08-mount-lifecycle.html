Single-SPA

// End-to-End Testing — Example 08
// Focus: mount lifecycle | Scenario: legacy migration

// Jest — unit-test activity functions and lifecycles
import { productsActive } from "./activity";

test("productsActive matches /products", () => {
  expect(productsActive({ pathname: "/products/1" })).toBe(true);
  expect(productsActive({ pathname: "/cart" })).toBe(false);
});

// Mount/unmount with a fake domElement
test("mount writes content", async () => {
  const domElement = document.createElement("div");
  const { mount, unmount } = await import("./lifecycles");
  await mount({ name: "@org/x", domElement });
  expect(domElement.textContent).toContain("@org/x");
  await unmount({ domElement });
});

Practice Notes

Checklist for End-to-End Testing
- Practice: mount lifecycle
- Scenario: legacy migration
- Register apps in the root config, then call start() once
- Use activity functions / activeWhen for path-based mounting
- Share dependencies via import maps; override locally for development
- Prefer parcels for framework-agnostic widgets; utility modules for shared logic
- Handle load/mount errors with addErrorHandler and layout error UI

Useful commands:
  npx create-single-spa
  # or generate root-config / react-app / vue-app / angular-app
  npm start

Notes

This example shows one way to apply End-to-End Testing in a legacy migration context.

Keep micro-frontends independently deployable, share carefully via import maps, and always plan for load failures.
