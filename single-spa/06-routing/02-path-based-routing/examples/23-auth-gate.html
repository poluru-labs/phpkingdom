Path-Based Routing

Section: Routing

Study the single-spa root/micro-frontend pattern and adapt it to your shell.

Single-SPA

// Path-Based Routing — Example 23
// Focus: auth gate | Scenario: SaaS dashboard

import { registerApplication, start } from "single-spa";

registerApplication({
  name: "@org/products",
  app: () => System.import("@org/products"),
  activeWhen: (location) => location.pathname.startsWith("/products"),
});

registerApplication({
  name: "@org/profile",
  app: () => System.import("@org/profile"),
  activeWhen: ["/profile"],
});

start({ urlRerouteOnly: true });

Practice Notes

Checklist for Path-Based Routing
- Practice: auth gate
- Scenario: SaaS dashboard
- Register apps in the root config, then call start() once
- Use activity functions / activeWhen for path-based mounting
- Share dependencies via import maps; override locally for development
- Prefer parcels for framework-agnostic widgets; utility modules for shared logic
- Handle load/mount errors with addErrorHandler and layout error UI

Useful commands:
  npx create-single-spa
  # or generate root-config / react-app / vue-app / angular-app
  npm start
  # Import Map Overrides UI: enable local micro-frontend URLs

Notes

This example shows one way to apply Path-Based Routing in a saas dashboard context.

Keep micro-frontends independently deployable, share carefully via import maps, and always plan for load failures.
