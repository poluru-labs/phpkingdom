Karma

// Testing Frameworks — Example 02
// Focus: single browser run | Scenario: legacy SPA

// frameworks: which assertion/runner adapter Karma loads
// Common: jasmine | mocha (+ chai) | qunit

module.exports = function (config) {
  config.set({
    frameworks: ["jasmine"],
    // npm i -D karma-jasmine jasmine-core
  });
};

// Mocha + Chai alternative:
// frameworks: ["mocha", "chai"]
// npm i -D karma-mocha mocha karma-chai chai

describe("framework pick", function () {
  it("uses Jasmine expect here", function () {
    expect(["jasmine", "mocha"]).toContain("jasmine");
  });
});

Practice Notes

Checklist for Testing Frameworks
- Practice: single browser run
- Scenario: legacy SPA
- Prefer ChromeHeadless (+ CI flags) for automation
- Keep singleRun/autoWatch gated on process.env.CI
- Pair frameworks (Jasmine/Mocha) with explicit plugins[]
- Add junit + coverage reporters for CI gates
- Open /debug.html with headed Chrome when diagnosing flakes

Useful commands:
  npm i -D karma karma-jasmine jasmine-core karma-chrome-launcher
  npx karma init
  npx karma start --single-run
  npx karma start --browsers=Chrome

Notes

This example shows one way to apply Testing Frameworks in a legacy spa context.

Adapt frameworks, browsers, reporters, and file patterns to match your stack.
