Karma

// Karma vs Jest — Example 05
// Focus: mocha suite | Scenario: design system

// Karma vs Jest — when each fits
// Jest: Node-first, jsdom by default, built-in runner + assertions + mocks
// Karma: real browsers, pairs with Jasmine/Mocha, great for Angular / DOM / polyfills

// Jest (Node/jsdom):
// test("sum", () => expect(1 + 1).toBe(2));

// Karma + Jasmine (real Chrome):
module.exports = function (config) {
  config.set({
    frameworks: ["jasmine"],
    files: ["src/**/*.js", "src/**/*.spec.js"],
    browsers: ["ChromeHeadless"],
    singleRun: true,
  });
};
// Tip: use Jest for pure logic; Karma when you need real browser APIs

Practice Notes

Checklist for Karma vs Jest
- Practice: mocha suite
- Scenario: design system
- Prefer ChromeHeadless (+ CI flags) for automation
- Keep singleRun/autoWatch gated on process.env.CI
- Pair frameworks (Jasmine/Mocha) with explicit plugins[]
- Add junit + coverage reporters for CI gates
- Open /debug.html with headed Chrome when diagnosing flakes

Useful commands:
  npm i -D karma karma-jasmine jasmine-core karma-chrome-launcher
  npx karma init
  npx karma start --single-run
  npx karma start --browsers=Chrome

Notes

This example shows one way to apply Karma vs Jest in a design system context.

Adapt frameworks, browsers, reporters, and file patterns to match your stack.
