Least-Privilege Access

Section: Security

Focus: Batch Write

Scenario: IoT telemetry

Study the DynamoDB Document Client pattern and adapt it to your access patterns.

DynamoDB (Node.js SDK v3)

// Least-Privilege Access — Example 10
// Focus: batch write | Scenario: IoT telemetry

export const leastPrivilegePolicy = {
  Effect: "Allow",
  Action: ["dynamodb:GetItem", "dynamodb:Query", "dynamodb:PutItem", "dynamodb:UpdateItem"],
  Resource: ["arn:aws:dynamodb:us-east-1:123:table/AppTable", "arn:aws:dynamodb:us-east-1:123:table/AppTable/index/*"],
};

Practice Notes

Checklist for Least-Privilege Access
- Practice: batch write
- Scenario: IoT telemetry
- Design for access patterns first (Query over Scan)
- Prefer Document Client for app code; raw client for admin
- Use ConditionExpression for idempotency / optimistic locking
- Paginate with ExclusiveStartKey / LastEvaluatedKey

Useful commands:
  npm install @aws-sdk/client-dynamodb @aws-sdk/lib-dynamodb
  docker run -p 8000:8000 amazon/dynamodb-local
  aws dynamodb list-tables --endpoint-url http://localhost:8000
  node index.mjs
