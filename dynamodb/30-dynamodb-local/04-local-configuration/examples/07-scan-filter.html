Example 07

Local Client Configuration

Section: DynamoDB Local

Focus: Scan Filter

Scenario: multi-tenant SaaS

Study the DynamoDB Document Client pattern and adapt it to your access patterns.

DynamoDB (Node.js SDK v3)

// Local Client Configuration — Example 07
// Focus: scan filter | Scenario: multi-tenant SaaS

import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient } from "@aws-sdk/lib-dynamodb";
export function localDoc() {
  return DynamoDBDocumentClient.from(new DynamoDBClient({
    region: "us-east-1",
    endpoint: process.env.DDB_ENDPOINT || "http://localhost:8000",
    credentials: { accessKeyId: "local", secretAccessKey: "local" },
  }));
}

Practice Notes

Checklist for Local Client Configuration
- Practice: scan filter
- Scenario: multi-tenant SaaS
- Design for access patterns first (Query over Scan)
- Prefer Document Client for app code; raw client for admin
- Use ConditionExpression for idempotency / optimistic locking
- Paginate with ExclusiveStartKey / LastEvaluatedKey

Useful commands:
  npm install @aws-sdk/client-dynamodb @aws-sdk/lib-dynamodb
  docker run -p 8000:8000 amazon/dynamodb-local
  aws dynamodb list-tables --endpoint-url http://localhost:8000
  node index.mjs

Notes

This example shows one way to apply Local Client Configuration in a multi-tenant saas context.

Model for queries, keep partition keys well distributed, and use GSIs only when access patterns require them.
