DynamoDB (Node.js SDK v3)

// DynamoDB Document Client — Exercise 15
// Focus: version check | Scenario: session store

import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient, PutCommand } from "@aws-sdk/lib-dynamodb";
const doc = DynamoDBDocumentClient.from(new DynamoDBClient({ region: "us-east-1" }), {
  marshallOptions: { removeUndefinedValues: true },
});
export async function putNative(item) {
  await doc.send(new PutCommand({ TableName: "AppTable", Item: item }));
}

Practice Notes

Checklist for DynamoDB Document Client
- Practice: version check
- Scenario: session store
- Design for access patterns first (Query over Scan)
- Prefer Document Client for app code; raw client for admin
- Use ConditionExpression for idempotency / optimistic locking
- Paginate with ExclusiveStartKey / LastEvaluatedKey

Useful commands:
  npm install @aws-sdk/client-dynamodb @aws-sdk/lib-dynamodb
  docker run -p 8000:8000 amazon/dynamodb-local
  aws dynamodb list-tables --endpoint-url http://localhost:8000
  node index.mjs

Notes

This exercise shows one way to apply DynamoDB Document Client in a session store context.

Model for queries, keep partition keys well distributed, and use GSIs only when access patterns require them.
