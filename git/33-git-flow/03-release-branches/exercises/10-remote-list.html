# Release Branches — Exercise 10
# Focus: remote list | Scenario: api service


# Git Flow release branch (release-branches)
git switch -c release/1.2.0
git commit --allow-empty -m "chore(release-branches): release prep"
git switch main && git merge --no-ff release/1.2.0
git tag -a v1.2.0 -m "v1.2.0"

Practice Notes

Checklist for Release Branches
- Practice: remote list
- Scenario: api service
- Prefer small commits with clear messages
- Never rewrite shared history without coordination
- Use git status often before commit/push
- Prefer pull --rebase on feature branches; protect main

Useful companions:
  git status -sb
  git log --oneline --graph --decorate
  git reflog
  git restore --staged <file>
  git push --force-with-lease

Notes

This exercise shows one way to apply Release Branches in a api service context.

Commit often, review diffs before push, and keep main/master protected with reviews.
