# Git Commit Conventions — Example 23
# Focus: hook setup | Scenario: open source fork

# Team commit conventions (commit-conventions)
git config commit.template .gitmessage
printf '%s
' 'type(scope): subject' '' 'body' > .gitmessage
git add .gitmessage
git commit -m "chore(commit-conventions): add commit message template"

Practice Notes

Checklist for Git Commit Conventions
- Practice: hook setup
- Scenario: open source fork
- Prefer small commits with clear messages
- Never rewrite shared history without coordination
- Use git status often before commit/push
- Prefer pull --rebase on feature branches; protect main

Useful companions:
  git status -sb
  git log --oneline --graph --decorate
  git reflog
  git restore --staged <file>
  git push --force-with-lease

Notes

This example shows one way to apply Git Commit Conventions in a open source fork context.

Commit often, review diffs before push, and keep main/master protected with reviews.
