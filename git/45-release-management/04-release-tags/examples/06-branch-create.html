Git Commands

# Release Tags — Example 06
# Focus: branch create | Scenario: docs site

# Release tags (release-tags)
git tag -a v2.0.0 -m "release: v2.0.0 (release-tags)"
git push origin v2.0.0
gh release create v2.0.0 --generate-notes

Practice Notes

Checklist for Release Tags
- Practice: branch create
- Scenario: docs site
- Prefer small commits with clear messages
- Never rewrite shared history without coordination
- Use git status often before commit/push
- Prefer pull --rebase on feature branches; protect main

Useful companions:
  git status -sb
  git log --oneline --graph --decorate
  git reflog
  git restore --staged <file>
  git push --force-with-lease

Notes

This example shows one way to apply Release Tags in a docs site context.

Commit often, review diffs before push, and keep main/master protected with reviews.
