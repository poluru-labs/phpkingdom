jest.config.js

Section: Test Setup

Focus: Tobe Matcher

Scenario: Vue app

Study the Jest pattern and adapt matchers, mocks, or async flow to your project.

Jest

// jest.config.js — Example 03
// Focus: toBe matcher | Scenario: Vue app

/** @type {import('jest').Config} */
module.exports = {
  testEnvironment: "node",
  roots: ["<rootDir>/src"],
  verbose: true,
  clearMocks: true,
  restoreMocks: true,
  collectCoverageFrom: ["src/**/*.{js,ts}", "!src/**/*.d.ts"],
  coverageDirectory: "coverage",
  moduleNameMapper: {
    "^@/(.*)$": "<rootDir>/src/$1",
  },
};
// Prefer jest.config.js over package.json "jest" key for larger projects

Practice Notes

Checklist for jest.config.js
- Practice: toBe matcher
- Scenario: Vue app
- Keep arrange / act / assert clear and deterministic
- Clear or restore mocks between tests (clearMocks / restoreMocks)
- Prefer async/await with resolves / rejects over done()
- Mock at boundaries; avoid over-mocking pure logic
- Review snapshot diffs before updating

Useful commands:
  npm install --save-dev jest
  npx jest
  npx jest --watch
  npx jest --coverage
  npx jest -u

Notes

This example shows one way to apply jest.config.js in a vue app context.

Prefer clear arrange/act/assert structure and keep mocks close to the behavior under test.
