Example 06

Testing Async Await

Section: Async Testing

Focus: Number Range

Scenario: design system

Study the Jest pattern and adapt matchers, mocks, or async flow to your project.

Jest

// Testing Async Await — Example 06
// Focus: number range | Scenario: design system

async function getUser(id) {
  if (id <= 0) throw new Error("invalid");
  return { id, name: "Ada" };
}

test("await happy path", async () => {
  const user = await getUser(1);
  expect(user).toEqual({ id: 1, name: "Ada" });
});

test("await rejection", async () => {
  await expect(getUser(-1)).rejects.toThrow("invalid");
});

Practice Notes

Checklist for Testing Async Await
- Practice: number range
- Scenario: design system
- Keep arrange / act / assert clear and deterministic
- Clear or restore mocks between tests (clearMocks / restoreMocks)
- Prefer async/await with resolves / rejects over done()
- Mock at boundaries; avoid over-mocking pure logic
- Review snapshot diffs before updating
