// Snapshot Best Practices — Exercise 16
// Focus: node util | Scenario: design system

// ✅ Snapshot small, focused output (serializable props / markup fragments)
// ❌ Avoid dumping entire Redux stores or random timestamps

function Badge({ label }) {
  return `<span class="badge">${label}</span>`;
}

test("badge markup is stable", () => {
  expect(Badge({ label: "New" })).toMatchInlineSnapshot(
    `"<span class=\"badge\">New</span>"`
  );
});

// Prefer explicit matchers for business rules; snapshots for structure

Practice Notes

Checklist for Snapshot Best Practices
- Practice: node util
- Scenario: design system
- Keep arrange / act / assert clear and deterministic
- Clear or restore mocks between tests (clearMocks / restoreMocks)
- Prefer async/await with resolves / rejects over done()
- Mock at boundaries; avoid over-mocking pure logic
- Review snapshot diffs before updating
