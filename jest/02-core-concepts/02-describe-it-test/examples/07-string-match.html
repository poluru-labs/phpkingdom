describe, it and test

Section: Core Concepts

Focus: String Match

Scenario: auth service

Study the Jest pattern and adapt matchers, mocks, or async flow to your project.

Jest

// describe, it and test — Example 07
// Focus: string match | Scenario: auth service

describe("Cart", () => {
  describe("addItem", () => {
    it("increments quantity for existing sku", () => {
      const cart = [{ sku: "A", qty: 1 }];
      cart[0].qty += 1;
      expect(cart[0].qty).toBe(2);
    });
  });

  // test() is an alias of it()
  test("starts empty", () => {
    expect([]).toHaveLength(0);
  });
});
// Use describe for grouping; prefer one behavior per it/test

Practice Notes

Checklist for describe, it and test
- Practice: string match
- Scenario: auth service
- Keep arrange / act / assert clear and deterministic
- Clear or restore mocks between tests (clearMocks / restoreMocks)
- Prefer async/await with resolves / rejects over done()
- Mock at boundaries; avoid over-mocking pure logic
- Review snapshot diffs before updating

Useful commands:

  npx jest --coverage
  npx jest -u
