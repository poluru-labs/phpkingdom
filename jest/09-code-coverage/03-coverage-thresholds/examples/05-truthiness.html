Coverage Thresholds

Section: Code Coverage

Focus: Truthiness

Scenario: Node CLI

Study the Jest pattern and adapt matchers, mocks, or async flow to your project.

Jest

// Coverage Thresholds — Example 05
// Focus: truthiness | Scenario: Node CLI

/** @type {import('jest').Config} */
module.exports = {
  coverageThreshold: {
    global: {
      branches: 70,
      functions: 80,
      lines: 80,
      statements: 80,
    },
    "./src/critical/": {
      lines: 95,
    },
  },
};
// Jest exits non-zero when thresholds are not met — great for CI gates

Practice Notes

Checklist for Coverage Thresholds
- Practice: truthiness
- Scenario: Node CLI
- Keep arrange / act / assert clear and deterministic
- Clear or restore mocks between tests (clearMocks / restoreMocks)
- Prefer async/await with resolves / rejects over done()
- Mock at boundaries; avoid over-mocking pure logic
- Review snapshot diffs before updating

Useful commands:
  npm install --save-dev jest
  npx jest
  npx jest --watch
  npx jest --coverage
  npx jest -u
