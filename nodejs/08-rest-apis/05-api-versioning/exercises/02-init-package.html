Exercise 02

API Versioning

Section: REST APIs

Focus: Init Package

Scenario: CLI tool

Run the code locally, then verify with curl, logs, or tests.

Node.js

// API Versioning — Exercise 02
// Focus: init package | Scenario: CLI tool

import express from "express";

const app = express();
const v1 = express.Router();
const v2 = express.Router();

v1.get("/users", (_req, res) => res.json([{ id: 1 }]));
v2.get("/users", (_req, res) => res.json({ data: [{ id: 1 }], meta: { version: 2 } }));

app.use("/api/v1", v1);
app.use("/api/v2", v2);
// Prefer URL versioning for public APIs; Accept header is an alternative
app.listen(3000);

Practice Notes

Checklist for API Versioning
- Practice: init package
- Scenario: CLI tool
- Prefer promises / async-await over nested callbacks
- Always handle errors; never leave streams without error listeners
- Use environment variables for secrets and config
- Validate inputs at API boundaries
